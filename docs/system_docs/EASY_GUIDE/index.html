2FA 쉽게 이해하기

이 문서는 프로그래밍을 처음 접하는 분도 2FA 스마트 도어락의 작동 원리를 이해할 수 있도록 비유와 그림으로 설명합니다.

2FA란 무엇인가요?​

2FA(Two-Factor Authentication, 이중 인증)란 신원을 확인할 때 두 가지 서로 다른 방법을 함께 사용하는 것입니다. 하나가 뚫려도 나머지 하나가 막아주기 때문에 훨씬 안전합니다.

실생활 속 2FA 비유​

flowchart LR
    subgraph ATM["은행 ATM"]
        A1[카드 삽입\n소유 확인] --> A2[비밀번호 입력\n지식 확인] --> A3[출금 완료]
    end
    subgraph Phone["스마트폰 잠금 해제"]
        B1[비밀번호 입력\n지식 확인] --> B2[지문 인식\n신체 확인] --> B3[화면 잠금 해제]
    end
    subgraph Door["이 프로젝트"]
        C1[NFC 카드 또는 PIN\n소유·지식 확인] --> C2[얼굴 인식\n신체 확인] --> C3[도어락 열림]
    end

은행 ATM도, 스마트폰도 두 단계를 거치는 것처럼, 이 도어락도 두 단계를 거칩니다.

2FA 인증 전체 흐름​

sequenceDiagram
    participant 사용자
    participant 아두이노 as 아두이노 (입력기)
    participant 서버 as 파이썬 서버 (두뇌)
    participant AI as 비전 AI (눈)
    participant 도어락

    사용자->>아두이노: NFC 카드를 대거나 PIN 입력
    아두이노->>서버: 카드 번호 또는 PIN 전달
    서버->>서버: 데이터베이스에서 사용자 확인

    alt 1차 인증 성공
        서버->>AI: 카메라 켜서 얼굴 확인 요청
        AI->>사용자: 얼굴 스캔 및 눈 깜빡임 감지
        alt 진짜 사람이고 등록된 얼굴임
            AI->>서버: 인증 완료 신호 전달
            서버->>아두이노: 문 열기 명령 전송
            아두이노->>도어락: 릴레이 작동 (철컥!)
        else 사진 또는 등록되지 않은 얼굴
            AI->>서버: 인증 실패 신호 전달
            서버->>서버: 침입 시도 기록 및 알림 전송
        end
    else 1차 인증 실패
        서버->>서버: 실패 기록 후 거부
    end

핵심 기술 용어 설명​

2FA (이중 인증)​

두 가지 방법으로 확인하는 것입니다. 열쇠와 지문, 카드와 비밀번호처럼 서로 다른 종류를 조합합니다.

flowchart LR
    A[소유\n내가 가진 것\nNFC 카드] --> D{2FA 통과}
    B[지식\n내가 아는 것\nPIN 번호] --> D
    C[신체\n내가 나인 것\n얼굴 인식] --> D

YOLO (욜로, You Only Look Once)​

카메라 영상에서 사물을 실시간으로 찾아내는 인공지능입니다. 이름처럼 화면을 딱 한 번만 훑어봐도 얼굴, 스마트폰, 눈의 상태를 동시에 찾아냅니다.

flowchart TD
    A[카메라 영상 입력] --> B[YOLO 분석]
    B --> C{감지된 물체}
    C --> D[얼굴]
    C --> E[스마트폰 또는 화면]
    C --> F[눈 열림 / 닫힘]
    E --> G[스푸핑 차단\n인증 불가]
    D --> H[눈 깜빡임 확인 후\n얼굴 비교로 진행]
    F --> H

bcrypt (비크립트)​

비밀번호를 알아볼 수 없는 암호문으로 변환하는 방식입니다. 데이터베이스가 유출되더라도 원래 비밀번호는 알 수 없습니다.

flowchart LR
    A[원래 비밀번호\n예: 1234] --> B[bcrypt 변환]
    B --> C[암호문\n$2b$12$abc...xyz]
    C --> D[(데이터베이스 저장)]
    E[로그인 시도\n비밀번호 입력] --> F[bcrypt 비교]
    D --> F
    F --> G{일치 여부 판단}

SQLite (에스큐엘라이트)​

시스템의 기록장 역할을 하는 데이터베이스입니다. 등록된 사용자 정보, 출입 기록, 실패 기록을 표 형태로 저장합니다.

flowchart LR
    subgraph DB["SQLite 데이터베이스"]
        T1[users 테이블\nNFC UID, bcrypt PIN]
        T2[access_logs 테이블\n시간, 결과, 사진]
    end
    서버 --> T1
    서버 --> T2

Fail-Safe 원칙이란?​

Fail-Safe(페일 세이프)는 무언가 고장났을 때 가장 안전한 상태로 유지되는 원칙입니다. 이 시스템에서는 카메라가 연결되지 않거나 인공지능 모델을 불러오지 못하면 문을 열지 않고 잠금 상태를 유지합니다.

flowchart TD
    A{시스템 상태 확인} --> B{정상?}
    B -- 예 --> C[인증 절차 진행]
    B -- 아니오 --> D[잠금 상태 유지]
    D --> E[카메라 오류\n모델 로드 실패\n서버 응답 없음]

정리​

이 시스템은 세 가지 원칙으로 작동합니다.

  1. 두 번 확인합니다. NFC 또는 PIN → 얼굴 인식, 두 단계를 모두 통과해야 문이 열립니다.
  2. 속임수를 차단합니다. 사진이나 화면을 카메라에 들이대면 YOLO가 즉시 감지하고 차단합니다.
  3. 고장 시 잠급니다. 시스템의 일부가 작동하지 않으면 문을 열지 않고 잠금 상태를 유지합니다.
