# 제3장: 하드웨어와 소프트웨어의 완벽한 하모니

## 1. 문제: 멈춰버린 도어락
아두이노에서 `delay()` 함수를 써서 릴레이를 제어했을 때, 문이 열려 있는 3초 동안 시스템은 완전히 '먹통'이 되었습니다. 그 사이에 누군가 카드를 대거나 번호를 눌러도 아두이노는 반응하지 않았습니다. 이는 실제 사용 환경에서 매우 심각한 결함이었습니다.

## 2. 우리가 한 일: 비차단형(Non-blocking) 제어
조희은 팀원은 이 문제를 해결하기 위해 펌웨어 구조를 완전히 뒤바꿨습니다.

- **millis() 기반 타이머:** `delay()`를 모두 제거하고 현재 시간을 체크하는 `millis()` 방식으로 변경했습니다. 이제 문이 열려 있는 동안에도 아두이노는 계속해서 다른 입력을 감시합니다.
- **시리얼 프로토콜 최적화:** 서버와 주고받는 메시지를 `WAKEUP:NFC:UID`와 같은 명확한 규격으로 통일하여 통신 오류를 최소화했습니다.
- **디바운싱 기술:** 키패드의 기계적 노이즈로 인해 숫자가 여러 번 입력되는 현상을 소프트웨어적으로 완벽히 잡아냈습니다.

## 3. 완성: 부드럽고 끊김 없는 경험
이제 우리 도어락은 문이 열리는 중에도 다음 사용자의 입력을 받을 준비가 되어 있습니다. 하드웨어의 한계를 소프트웨어적 사고로 극복한 값진 경험이었습니다.
