# 제2장: 보안의 정석, 취약점과의 사투

## 1. 발견: 편리함 뒤에 숨은 독, Pickle
개발 초기, 얼굴 인코딩 데이터를 저장하기 위해 우리는 파이썬의 `pickle` 라이브러리를 사용했습니다. 매우 편리했기 때문입니다. 하지만 김현우 팀원이 보안 분석을 진행하던 중, `pickle`이 '원격 코드 실행(RCE)' 공격에 취약하다는 사실을 발견했습니다.

해커가 악성 코드가 포함된 얼굴 데이터를 등록하면 우리 서버의 제어권을 통째로 넘겨줄 수 있는 치명적인 구멍이었습니다.

## 2. 우리가 한 일: 과감한 삭제와 재설계
우리는 이 문제를 발견한 즉시 다음과 같은 조치를 취했습니다.

- **Pickle 코드 영구 삭제:** 편리함을 포기하고 보안을 택했습니다. 프로젝트 내의 모든 `pickle` 관련 모듈을 삭제했습니다.
- **안전한 데이터 형식 도입:** 얼굴 데이터 앞에 `FACE128F64:`라는 고유 접두사를 붙이고, 오직 숫자 데이터만 안전하게 파싱하는 새로운 로직을 구축했습니다.
- **Fail-Safe 철학 적용:** "애매하면 열지 않는다"는 원칙을 세웠습니다. AI 모델이 로드되지 않거나 카메라에 이상이 생기면 무조건 출입을 거부하도록 로직을 강화했습니다.

## 3. 결과: 신뢰할 수 있는 시스템
이 과정을 통해 우리 시스템은 단순히 '작동하는 소프트웨어'를 넘어, '믿을 수 있는 보안 솔루션'으로 거듭났습니다. 보안 보고서를 작성하며 우리는 엔지니어가 가져야 할 책임감을 배웠습니다.
